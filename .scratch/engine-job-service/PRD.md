# 独立引擎任务服务：产品与技术设计

状态：implemented，本机验收完成 · 日期：2026-11-11

## 1. 目标与已确认决策

本项目默认作为面向客户、支持多人同时生成、检查和导出的产品设计。独立引擎服务应承担全部在线 Chrome 检查、预览渲染与PPTX/PDF导出；业务Node只提交固定输入的任务、查询状态和使用结果，不启动浏览器或直接执行引擎模块。

用户已确认：

- 业务Node和引擎可部署在不同机器，不依赖共享本地目录，以固定版本输入和任务ID协作。
- 引擎中已排队任务自动接续；仅因进程退出或租约失效而中断的执行最多自动重跑一次；确定性输入错误不重试，导出不重复扣点。
- 模型调用结果未知仍需用户同意，不因为引擎自动恢复而自动重发模型请求。

用户未规定人数/响应时间，要求不因设计明显增加等待。下述5用户混合/10用户突发及性能门槛已由用户确认；不是生产吞吐承诺。

本期采用用户确认的 A 范围：不包括多个业务Node副本对同一作品的故障接管。引擎多实例和业务Node/引擎分机属于本期目标；业务Node跨副本接管还要求将所有项目资料、页面、草稿、候选、检查点及模型响应从当前本地artifact目录改为跨副本可取的权威存储。不能仅完成引擎HTTP拆分就声称整站多副本高可用。业务 Node 跨副本接管留待后续独立实施。

## 2. 当前事实与必要变化

- `src/http/engineServer.ts` 已有同步检查/预览/导出接口，但预览/导出依赖调用者本机runDir，并且仅接受deck根目录直接子目录，不能直接服务当前revision目录。
- `src/capabilities/agent.ts`、`deck.ts` 仍直接运行Chrome校验、缩略图和export-only。engineServer还反向调用业务Capability，必须分离，否则客户端改走HTTP后会递归调用自己。
- Capability默认一个队列混合生成、检查、预览与导出；Brain默认一个长任务worker。只改HTTP调用会保留整份生成串行和长导出阻塞短任务的问题。
- Go现有任务/预算和文件域可复用；现有导出文件API仅支持PPTX/PDF，不能直接放宽为任意输入文件上传/下载。新增引擎私有输入/输出artifact接口，不改变普通客户下载授权。
- 现有导出回执以Node进程内inFlight和本地JSON协调，多业务副本需要使用Go原子幂等记录，不能依靠不同机器的本地回执防止重复收费。

## 3. 方案比较与选择

| 方案 | 取舍 | 结论 |
|---|---|---|
| 同机独立进程、共享目录 | 改动较少，但仍绑定目录及机器，跨机器还要重新设计交付 | 用户未选择 |
| 固定输入artifact＋持久异步任务＋独立引擎执行 | 增加任务协议和输入传输，业务与引擎可独立扩容、重启，结果可恢复 | 用户选择；本设计落实 |

沿用Go/TypeScript/Python，不新增Redis或外部Agent框架。开发仍可用本机四进程，客户生产部署应使用现有PostgreSQL与文件存储能力承载共享状态。本地JSON仅是单网关开发后端，不作为多副本生产方案。

## 4. 服务边界与执行链

1. 业务Node读当前不可变revision或页面候选，构造输入快照，上传到Go的引擎私有artifact域。
2. 业务Node以用户归属、来源版本、操作ID提交引擎任务，立即获得`engine_job_id`。相同幂等身份返回已有任务。
3. 引擎worker从Go领取任务和租约，按artifact_id下载并核对固定输入，在自己机器创建临时工作区。
4. 引擎执行检查、渲染或导出，更新阶段/心跳，将报告或文件写入引擎artifact域，再以租约身份提交结果。
5. 业务Node获取状态与结果，按原Agent执行权/父修订条件提交检查或页面结果。引擎完成旧版本任务不代表可以覆盖新作品版本。
6. 客户已授权的导出由业务层完成幂等计费，成功后才向客户交付下载；引擎不接收客户业务Bearer Key，也不自行计费。

Go独占任务/租约/幂等记录，Node独占项目版本，Engine独占浏览器作业。Python仍负责模型决策，不直接操作引擎数据库或文件系统。

## 5. 固定输入与文件交付

输入快照包含schema版本、deck_id、可选revision_id、来源类型、按page_id排序的manifest、页面HTML及聚合deck.html、所需内嵌资源和内容摘要。候选校验使用candidate内容摘要；旧作品由当前文件生成一次请求快照，不为只读渲染强制迁移作品。

- 业务工作区绝对路径不得进入引擎任务协议；引擎的本地输出路径也不作为客户结果返回。
- 优先采用单个结构化快照，不使用任意路径解压协议；按请求体/总输入大小和引擎任务kind约束内容。
- 服务私有artifact按owner/deck/source_hash关联，输入只写一次；发布后修改源HTML不影响已有任务。
- 引擎只从配置的Go文件服务读取artifact_id，不按任务提供的任意URL下载文件。
- 私有输入、截图和报告不进入现有客户导出文件列表。产物分别返回报告引用、预览文件引用或PPTX/PDF引用。
- 引擎任务输出可以先私有落盘；客户导出成功交付复用现有Go文件域和鉴权下载。已完成文件可复用，但计费未成功前不能向客户发布可访问下载链接。

跨机器验收中，业务目录与引擎目录必须分离且互不可读；测试不能仅因为同机共享路径而通过。

## 6. 任务协议和生命周期

主要DTO（具体路由名在实施计划中确定）：

```text
SubmitEngineJob = {
  owner_key_hash, deck_id, source_revision_or_hash, snapshot_id,
  kind: validate | inspect | export,
  page_ids, format?, profile_version, operation_id,
  optional agent_execution_key
}
EngineJob = {
  engine_job_id, state, stage, attempt, worker_epoch,
  source_ref, progress, result_refs, error,
  queued_at, started_at, finished_at, lease_until
}
state = queued | running | completed | failed | cancelled
```

- Go原子创建任务及幂等身份。身份至少包含归属、deck、固定来源摘要、操作种类、页集合/格式和渲染配置版本；相同operation_id不同内容报冲突。
- claim/心跳/完成/失败/取消采用条件更新。所有重试和迟到结果绑定attempt与worker_epoch，旧worker不能完成新尝试或提交取消任务。
- 输入快照上传完成后才允许排队。结果文件全部写入并有完整回执后才标completed，不暴露半成品。
- 复用仓库已有重复start返回同一活动作业的约定：相同归属、来源、种类和参数返回同一个活动任务；完成结果可复用。同任务在两个窗口打开时，取消作用于该共享任务，两个窗口同步显示已取消，界面须说明。取消/失败后主动再次提交使用新的operation_id创建新任务；重复请求旧operation_id仍返回原终态，不能偷偷重置重试次数。已交付成功的导出不能再取消。
- inspect可在一次页面加载中完成布局检查和截图，避免重复打开Chrome；已有有效产物按固定来源和profile复用。
- 引擎支持状态查询和取消。浏览器断开不取消任务；显式取消清理该任务自己的资源，不能关闭其他任务使用的浏览器。
- Node可为现有薄适配层短暂等待结果，但不能占住LLM/引擎执行槽位；外部导出采用开始任务、展示进度、完成后下载，避免长HTTP连接承载整份导出。
- 校验/预览的旧调用形状由薄客户端等待结果适配；HTTP、MCP、CLI、WPS都走独立引擎客户端，不保留本地渲染后门。WPS需处理异步导出回执，但不新增完整Harness交互。

## 7. 多用户调度与等待时间

工程初值：Brain最多5个活跃项目worker；沿用每份作品页面模型并发2；本机引擎每实例默认限制1个同时运行的Chrome作业，服务器按压测调整。参数允许按已测CPU/内存调整，不以用户数直接等同Chrome进程数，也不增加模型默认费用预算。

- 移除覆盖整份生成、检查和导出的共享长任务槽位；模型工作和引擎工作各有容量控制。等待引擎结果不得占模型调用槽位。
- 使用有界持久队列，按当前鉴权归属（业务Key的owner hash）轮转公平派发；同用户大量任务不能插队或占满全部可用槽位。
- 校验/预览与长导出分别排队，短任务获得优先调度机会，同时用有界权重保证导出不会饿死。已在运行的任务不因新短任务被抢占或重新开始。
- 所有槽位忙时仍然需要等待；不得承诺多人任务等同单用户耗时。状态接口和网页应保持响应，显示排队/执行/完成，不用伪进度掩盖排队。
- 单独因引擎排队而等待不扣Agent有效执行时间；同一Agent若仍有模型请求或引擎作业在运行，则按墙钟计时一次，不按并发数量叠加。引擎租约和作业超时从实际开始执行计，不从提交计。
- 模型供应商限速或机器资源不足与HTTP拆分开销分别记录，不用临时无限并发或提高预算凑验收。

## 8. 恢复、取消与扣点

- Go保存排队任务，任意健康引擎可继续领取；引擎重启不要求客户重新提交同一任务。
- 运行任务心跳租约失效或确认worker退出时，允许一次自动重新执行；不是每次服务启动都重置attempt。第二次仍失联则failed。
- 输入无效、确定性转换失败、客户取消、达到作业执行超时均明确结束，不自动重试；自动重试不包括模型调用。
- 浏览器/page/context必须归任务或worker所有，单任务失败/取消只清理自己的资源。
- Go幂等导出记录涵盖输出引用、计费操作ID和交付阶段；完成后重复请求返回同一结果。先有有效产物，再按同一计费ID扣一次点，最后开放客户下载。
- 若扣点后响应丢失，重复请求查回原交付回执，不再次扣点；同一来源已导出但后续换成新revision属于新导出身份。
- 新引擎任务自动恢复不自动恢复中断的Agent模型决策；保持已有用户“继续”语义。已存在引擎结果在Agent继续时复用。

## 9. 建议验收规模与可衡量门槛

验收目标为设计建议，不是已经测得的性能：

| 组别 | 负载 | 重点 |
|---|---|---|
| 单用户基线 | 固定6页/20页HTML，分别检查、预览、PPTX、PDF；重构前后同机同配置暖启动重复至少5次 | 排除模型抖动，检查服务拆分的新增开销 |
| 常态混合 | 5个独立业务Key的生成任务同时推进，并混合检查/预览/导出；涵盖6页和20页 | 用户隔离、公平性、短任务不被单个长导出串行卡住 |
| 突发 | 10个用户同时提交混合作业 | 有界并发、可见排队、无丢任务/重复扣点/内存失控 |
| 故障 | 排队重启、运行中退出、取消、结果落盘后回执前退出、扣点后响应丢失 | 固定输入、最多一次恢复、旧worker失效、交付幂等 |

单任务检查/预览/导出各自的暖启动中位耗时，相比拆分前增量目标不超过`max(10%, 0.5秒)`；统计上传、等待、执行、交付耗时，不能只报Chrome时间。状态查询/任务提交P95目标1秒以内（测试环境本机服务网络，模型工作和完整大文件上传不计入该接口延迟）。

并发下不保证总完成时间与单任务相同。要求下一次槽位可派发时按用户与任务种类公平取任务；不能等待整份长生成完成才处理别人预览。记录每类任务P50/P95排队与完成耗时、峰值内存、重试/失败数，并依据结果调并发或指出容量缺口，不能以“支持5人”代替数据。

使用本地假模型固定响应与已生成HTML跑主要并发验收，真正渲染/导出使用Chrome；不默认向真实供应商发起批量付费模型调用。跨机器能力可通过隔离目录/只允许HTTP取artifact的集成环境验证，不要求立刻租用云服务器；实际远程网络延迟不能伪称已实测。

本机当前约15GB物理内存，读取时约1GB空闲；该瞬时状态不能用于证明生产容量。压测记录硬件和可用内存，不擅自关闭用户其他程序。若资源不足，报告容量和未通过项，不增加无限排队或降低检查质量。

## 10. 代码边界、迁移与交付

- 契约：更新`src/contracts/engine.ts`和`contracts/openapi/engine.yaml`，补任务/私有artifact/幂等导出协议。
- Go：在现有任务与文件边界内加入引擎任务、输入/输出artifact、租约/公平调度与交付记录；沿用JSON开发/PG生产两种后端的明确边界。
- Engine：从业务Capability提取确定性执行器，由engineServer/worker独占Chrome及export-only；不能反向依赖业务Agent、模型、计费模块。
- Capability：新增引擎任务客户端；agent.ts/deck.ts所有在线Chrome入口改为提交/等待结果，保留静态HTML方言校验和项目版本管理。
- Brain：有界项目并发，正确处理引擎队列等待与现有预算/执行身份；不改变单总控产品策略。
- Web/WPS/CLI/MCP：适配结果/异步导出状态，不改用户已确认的PPT内容；本地dev仍四进程，引擎不可用明确报错，不退回业务进程渲染。
- 测试：跨目录隔离、调用可达性审计、任务幂等/取消/恢复、并发公平、版本绑定、扣点和跨用户权限；新增测试覆盖真实行为，不复制实现断言。
- 文档：追加新的ADR，明确调整总纲中“进程内直调”的运行边界与ADR-0035旧导出限制的具体适用范围；不改写旧accepted ADR。更新部署、当前状态、CHANGELOG，记录验收数据和未验证环境。

本设计不重写HTML/PPTX转换算法，不更换模型，不开发完整账号系统或云自动扩容，不引入新的付费基础设施。引擎任务协议应能支持多实例；不能仅用当前同机开发环境代替客户部署边界。

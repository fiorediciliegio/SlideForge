# 优化1：检查按需自动推进

日期：2026-11-14。用户已逐项确认Q1–Q5并授权实现。本次只实施优化1，不实施多页批量修订、通用上下文精简、并发提升或降低思考强度。

## 已确认行为

- 程序根据当前版本缺失/失效的检查安排工作；有效证据和评审复用，不重复全量检查。
- 初检顺序为程序版面→全稿内容→分批视觉，视觉每批最多4页。内容/视觉由模型分开判断，程序不伪造模型结论。
- 同一阶段先收齐问题再返工；仍使用现有单页工具逐页修订。未修完已知问题前不反复全稿复核；这一轮结束补齐当前版本全稿内容评审。
- 模型保留资料读取、有具体理由的追加检查、修订和请求用户的能力。每页两次返工上限与预算规则不变。
- 无阻断项、所有必需检查及已授权导出完成后，程序调用现有finish逻辑，保留完成回执、当前质量修订及Go条件提交。
- 已确认的大纲、版本/epoch隔离、取消、中断恢复、未知调用不自动重发均不放宽。

## 技术决定

复用Node检查artifact与指纹判断。新增内部`_review_next`只供Brain取得下一项检查工作；它可以组合有效旧证据为当前批次的观察artifact，不调用模型或自行评审。Python在模型回合之间执行确定性检查/导出/收尾，只有语义/视觉判断与修订才交给模型。按项目修订与任务内容生成稳定操作ID，崩溃后复用现有工具回执，不另建任务框架或Go状态字段。

调度通过现存证据推导：先处理有效版面/内容阻断项；视觉阶段存在未评审页时继续收齐，齐全后才处理视觉阻断项。修订使旧问题在被改页失效，未改页问题仍保留；因此可逐页修完已有清单，再复核受影响页及当前全稿。

## 验证

先写窄测试锁定检查顺序、4+2分批、证据复用、阶段问题汇总、自动完成/授权导出、恢复和取消边界。运行Python单测、Node相关用例，再运行`npm run check`和`npm run test:core`。不调用真实模型，不修改固定测评协议或历史基线；真实模型测评预算完成后另行确认。

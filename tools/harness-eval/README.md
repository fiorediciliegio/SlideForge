# Harness 固定测评基准 v1

后续性能测评使用本工具：每轮只运行当前工作区的6个案例，直接读取已保存的历史成绩，不再启动或重跑旧版代码。当前业务代码的未提交修改也会参与运行，并保存源码哈希。

## 修订范围与单页16000配置

使用`--profile repair-scope-16000`：总控8192、单页16000、页面并发2，其余6类案例/6页/模板/评分规则与每例预算不变。主参考为第二项修改前的`20261114-review`；辅助参考为上一轮`20261114-revision-batch`。历史协议和结果均不覆盖。

```powershell
npm.cmd run eval:harness -- --profile repair-scope-16000 --check
npm.cmd run eval:harness -- --profile repair-scope-16000 --preflight
# 本轮真实模型预算另行授权；15元仅为示例
npm.cmd run eval:harness -- --profile repair-scope-16000 --run --budget-cny 15
```

输出位于`.eval-results/harness/v3-16000/<UTC运行ID>/`。`page-metrics.mjs`只读已有响应、逐页回执和按页面指纹匹配的首轮检查；不调用模型或Chrome。历史补算保存在`metrics-baselines-16000.json`，采集脚本和数据均由配置SHA256校验。

- 截断率：页面响应中`finish_reason=length`的比例，未知模型结果另列。
- 首次程序通过率：目标36页中，首次页面请求返回完整HTML、方言及程序版面校验通过的比例；之后重做不补计成功。
- 初稿无需必要返工率：首次程序通过，且首轮内容、视觉无阻断；非阻断建议不算失败。
- 缺失响应/检查为未知，未调用页为未执行。整例采集失败还会报告未采集页数，不把缺失证据视为通过。历史记录的`source`路径需仍可读取才能重新补算，已冻结的汇总不依赖再次补算。

## 固定内容

- 企业产品、品牌、活动、学术、旅游、长资料6类虚拟案例，资料和附件位于 `fixtures/v1/`。
- 每份固定6页，直接生成、禁止联网检索、每任务600有效秒/2元估算预算，900秒墙钟截止。
- 模型固定 `deepseek-flash`，页面输出上限12000、总控4096 token，沿用产品思考配置。
- PPT模板固定 `134-Adaptive Systems Editorial Cover`，保存实际注入的10000字符参考快照。
- 沿用已使用的预览/事实/章节/越界评分器、PPTX结构检查和模型预算代理；不随业务优化改变评分规则。
- Windows checkout通过本目录的 `.gitattributes` 保留原始换行。材料、参考模板、评分器和基线均校验SHA256；校验失败停止运行。

固定的是测评输入和规则，生成的页面仍由当前模型与代码产生，不要求复用旧PPT内容。

## 批量修订与8192总控配置

`--profile revision-batch-8192` 显式采用独立的8192运行协议，页面仍12000，其余材料、6页、模板、评分器、每例预算与v1相同。冻结的`proxy.mjs`、`suite-v1.json`及历史基线不改；新配置和独立代理分别位于`profiles/revision-batch-8192.json`与`proxy-8192.mjs`，按SHA256校验。

主要参考为`20261114-review`（上一轮检查自动推进后的6例保存结果），同时保留其他历史参考。历史总控4096，本轮8192并加入批量修订，报告描述综合变更，不声称单变量因果。只运行新版，不重跑旧版。

```powershell
npm.cmd run eval:harness -- --profile revision-batch-8192 --check
npm.cmd run eval:harness -- --profile revision-batch-8192 --preflight
# 必须获得本轮真实模型预算授权后才执行；15元仅为示例
npm.cmd run eval:harness -- --profile revision-batch-8192 --run --budget-cny 15
```

新结果保存在`.eval-results/harness/v2-8192/<UTC时间ID>/`，metadata与protocol.json记录实际输出上限、协议哈希和比较口径。`--compare`会从metadata恢复该运行的配置，不发起模型请求。

## 使用方法

在项目根目录的PowerShell运行。默认及 `--check` 仅校验输入，不启动服务、不读取模型Key、不产生费用：

```powershell
npm.cmd run eval:harness -- --check
```

零费用服务预检仅启动本次隔离服务，健康检查后关闭，代理预算为0：

```powershell
npm.cmd run eval:harness -- --preflight
```

真实测评必须明确提供本轮总预算；以下15元是命令示例，不是自动授权，也不会沿用上一次测评的剩余预算：

```powershell
npm.cmd run eval:harness -- --run --budget-cny 15
```

运行前需按项目开发说明准备Node、Go、项目Python虚拟环境及Chrome，模型凭据使用项目 `.env`。工具按案例串行执行，每例启动独立四进程，端口48420–48424，使用独立数据目录；只关闭本次进程。供应商凭据仅留在预算代理，业务进程使用占位Key。未知结果不自动重发，不补跑失败或暂停案例。

结果保存在 `.eval-results/harness/v1/<UTC时间ID>/`：完整记录、请求/响应、用量账本、源码哈希、逐页预览、成功作品PPTX、`summary.json`和中文报告。该目录已被仓库忽略，不自动加入Git。

只重新汇总已有本工具运行的结果、不调用模型：

```powershell
npm.cmd run eval:harness -- --compare 'D:\SlideForge\.eval-results\harness\v1\<运行目录>'
```

## 统一比较口径

- 全部6次尝试均记录终态、交付率和累计费用。失败、等待用户、未知调用、预算暂停不替换为成功样本。
- 生成耗时包含规划、页面生成、检查和修订。导出单独计时，生成＋导出只比较双方导出检查通过的相同案例。
- 耗时、调用与费用的配对比较只取双方已交付的相同案例；不把一方提前暂停误认为提速，不直接比较不同成功子集的中位数。
- 费用同时按固定高峰无缓存2/8元每百万token及缓存输入0.04元重算。它是统一比较价格，不等于供应商账单；模型用量和当时段估算另外保留。执行前仍需核对供应商实际报价和当次预算，不含机器部署成本。
- 后续运行属于**历史基线回归比较**。不同日期的模型服务、缓存、硬件负载和自主返工可能变化，结果不能标成同轮严格A/B，也不将所有差值归因于代码。
- 每类各一轮，仅供趋势判断。首轮生成未触发页面/历史批量读取时，不宣称这两项的收益；自动检查也不代表人工视觉验收。

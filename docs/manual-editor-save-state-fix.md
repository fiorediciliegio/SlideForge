# 手动页面编辑器保存状态修复

## 变更目的

修复手动编辑器中“未修改页面却弹出保存确认”的问题，同时保留原有的保存、放弃修改和继续编辑流程。

## 修复内容

### 0. 工具栏和下拉控件交互优化

同步整理了本轮手动编辑器工具栏调整：

- 行距、段距和字号使用统一的可访问下拉控件，支持鼠标、键盘方向键、Enter/空格选择以及 Escape 关闭；
- 下拉菜单使用编辑器主题根节点和兜底颜色，避免菜单透明或层级异常；
- 工具栏在空间不足时压缩控件并分行布局，为右侧固定操作区预留空间，避免段落控件被截断；
- 保留插入、撤销/重做、字体、文字样式、对齐、行距/段距、颜色、删除/更多的功能顺序。

### 1. 保存确认改为比较实际文档内容

页面切换和离开编辑器时，不再直接把 `saveStatus` 当作是否有修改的依据，而是将当前页面 HTML 与最近一次成功加载或保存后的快照进行比较。

这样可以避免以下情况误触发保存确认：

- 双击文本只进入编辑状态，没有改变文字或样式；
- 上一次保存失败，但随后撤销操作已经恢复原内容；
- 保存状态标签仍显示错误，但文档本身已经回到基线。

保存失败状态仍会保留在界面上，便于用户发现失败并重试；保存确认只由实际文档差异决定。

### 2. 排除 Moveable 编辑器运行时节点

Moveable 在选中元素时会向页面文档注入 `style[data-styled-id]`，并创建拖拽、光标等临时节点。这些内容属于编辑器运行时状态，不属于 PPT 页面源文件。

快照序列化时现在会排除以下运行时内容：

- `style[data-styled-id]`；
- `.manual-editor-moveable`；
- `.manual-editor-svg-text-input`；
- `.manual-editor-caret`。

因此单纯双击、选中或进入文本编辑不会改变页面快照，也不会触发无意义的保存流程。

## 本地运行注意事项

本地 Harness 的会话只对当前开发服务进程有效。若 5180 端口被其他工作区的 `slideforge-app dev` 占用，刷新后可能看到 `unknown session_id`。测试当前分支前应确保只有当前工作区使用 5180 端口，并重新打开：

```text
http://localhost:5180/
```

该运行环境问题与本次页面保存状态代码无关，也不涉及账号登录或 LLM 配置。

## 提交范围

本次提交涉及手动页面编辑器的保存状态判断、快照序列化和工具栏交互样式，不改变云端存储协议或页面资源加载流程。

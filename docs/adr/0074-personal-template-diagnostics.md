# 个人模板工作目录、详细会话日志和问题排查包

个人模板入口恢复开放，首页可在内置模板和我的模板之间切换并手动选择。自动推荐继续只读取内置目录。

## 目录与生命周期

新建操作先在 `getPptWorkspaceRoot()/user-templates/<id>/` 分配草稿，再上传和保存原始 PPTX。
原件未保存也保留草稿，可下载已有排查材料；续跑时重新选择同名 PPTX。已保存的原件不可替换。
每次新建或继续创建使用新的 `creation_run_id`，复用模板目录和已经完成的母版、参考页，不覆盖旧日志。

模板仍是应用级资源，不初始化普通作品的 task、requirements、outline 或 generation transaction。
模板专用接口接收 ID，后端在模板根目录内解析并验证真实路径。普通作品的目录规则保持不变。

## 诊断记录

沿用 `VITE_PPT_LOG_ENABLED=true` 的唯一详细诊断开关；关闭时不产生新日志，不删除既有记录。
日志是尽力写入的旁路，失败不改变业务结果，也不导致业务操作重放。

模板 `.log/` 中包含：

- `user-template.jsonl`：创建、续跑、复用、上传原件保存、转图、HTML 保存与预览渲染、发布和终态。
- `ai-user-template-interactions.jsonl`：会话创建请求和结果、每次实际运行请求、完整输出或失败部分输出、解析重试、取消及删除。
- `ai-user-template-stream.jsonl`：SDK 交付给应用的原始帧，包括未知事件和工具字段。
- `storage-transport.jsonl`：前后端宿主上传、原件下载及 APS 发布阶段。
- `payloads/`：超过行内预算的大内容，保留路径、长度和 SHA-256 引用。

创建运行、操作、本地会话、平台会话、实际运行交互、平台运行和原始页码分别记录，不混用标识。
在创建平台会话前记录请求，因此创建失败也有证据；同会话修复和新会话重试都拥有独立记录。
帧接收序号从每次运行的 1 开始。原始帧在业务事件归一化前采集，按数量、体积或时间分批写入；
结束、失败、取消和下载前均冲刷已接收内容。写入故障和容量保护明确记录缺口，不承诺进程崩溃前尚未落盘内容可恢复。
签名地址、鉴权字段脱敏；用量计数、关联 ID、文件名和未知业务字段保留。原件和图片通过目录工件定位。

记录层级为 `session.run.payload`。完成判定保持原逻辑，停止观察后的帧和 SDK 未交付的外层消息不属于可观察范围。

## 下载对象与传输

从“我的模板”进入设置时使用个人模板诊断上下文；创建、续跑和预览会选择对应模板，设置页允许明确切换。模板卡片不展示诊断选择按钮或诊断选中描边。
没有目标时展示选择器并禁用下载，不回退上一份普通作品。切换目标或离开模板诊断上下文时清空旧链接并忽略过时请求的返回。
设置页显示模板名称和身份后缀；失败、取消、生成中和已经完成的模板均可下载。

下载仍受 `VITE_WORKSPACE_DIAGNOSTIC_BUNDLE_ENABLED=true` 控制。前端先冲刷有限的一批已接收日志，
引擎在日志目录锁内复制日志及附属文件，再打包该副本和模板的其他文件。其他文件沿用逐项稳定性检查；
变化时失败并重试。包内记录采集时间、对象和非原子快照语义，不修改模板本身。

共用目录归档和 APS 发布能力，模板使用 `user-templates/<id>/diagnostics/current-template.zip`。
临时文件完成后清理；宿主下载优先，不支持时保留短期链接后备。每个模板覆盖一个当前对象，不登记普通用户文件，
不新增排查包历史或个人模板跨设备同步。ZIP 包含用户原件和模型内容，沿用现有问题排查包敏感内容提示。

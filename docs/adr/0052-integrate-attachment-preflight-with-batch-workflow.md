# 将附件预处理接入完整批量流程

本决策记录 `feat/attachment-preflight-migration` 合入 `anna-ppt` 时的取舍，并补充 ADR-0012 中附件只通过独立 Agent 分析、只影响大纲的早期范围。

交互流程和批量流程都先完成附件预处理、必要的 PDF OCR（图片文字识别）续跑及附件上下文准备，再生成演示需求。需求确认后的批量编排继续使用 `anna-ppt` 的顺序：等待上传资料分析、执行 Web 研究、生成大纲、确认大纲、生成页面和导出；页面生成复用已有 Web 研究结果。保留页面修改分类评估、统一模型重试以及响应丢失后的持久状态恢复。

`attachment-context-created` 是新增的附件专项测试截止点，不是附件字段的适用范围限制。需求、研究、大纲、图片研究和完整 PPT 批量测试均可携带附件。输入可包含已有 Host Upload（宿主上传）引用，或仅给出文件名、由测试界面配对本地文件后上传；两种输入在开始执行前统一为相同的持久化附件记录。

PDF 预处理返回 `processing` 时，上下文策略暂为 `null`。批量流程必须先检查引擎是否支持续跑，并继续处理到识别结束；取消后不得继续生成附件上下文或演示需求。附件专项测试与完整测试共用这一处理路径。PDF OCR 失败仍采用警告后继续的策略，未识别内容进入附件警告，不宣称完整识别成功。

不同文件格式的附件解析、摘要校验和附件分析提示词均沿用 `feat/attachment-preflight-migration` 的实现。表格保留工作表边界、覆盖情况和证据引用关系校验，允许重新组织行文本，不额外施加逐字摘录校验；文档和 PDF 保留同事分支已有的摘录校验。

大纲生成、改写和页面 HTML 生成提示词恢复为合并前 `anna-ppt` 的实现。大纲原本已通过 `uploadedSourceAnalysisContext` 接收上传资料分析结果，不再追加独立的 `attachmentContext` 段落，以免重复提供同一批资料。页面 HTML 提示词不新增“当前页标题”行。附件分析提示词继续使用同事分支的版本。

回归覆盖各批量截止点的附件持久化、PDF 续跑与取消、旧引擎能力缺失、研究先于大纲、上下文传递、完整导出、表格重排摘录兼容，以及大纲生成和改写只包含一份上传资料分析结果。

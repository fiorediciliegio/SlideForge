# 用前端构建配置统一开关诊断日志

PPT App 用现有 `.env` 的 `VITE_PPT_LOG_ENABLED` 作为唯一配置来源。仅 `true`
开启，缺失或其他值关闭，不引入日志级别或后端环境文件。

前端在 `PptBackend` 适配层阻止停用日志的序列化、Host Upload 和工具调用；AI 日志
仍分配关联标识、保留性能计数，但不计算诊断内容哈希或读取仅用于日志的会话历史。
普通调用与异步作业都在原有 `args` 中携带布尔值 `diagnostic_logging_enabled`，
沿用现有通用 `performance_context` 参数的运行时 manifest 扩展方式，不修改协议封装。

后端每次调用绑定日志上下文，并让衍生异步任务继承，避免并发调用互相改变记录策略。
引擎独立定时任务使用最近收到的配置；启动和未传值的调用默认关闭。配置不写入作品，
后端重启通过下一次调用恢复。工作区日志入口在任何工作区初始化、载荷下载或附属文件
写入前短路；快照恢复计时记录使用同一开关。业务异常及工具响应仍正常返回。

本决策修订 ADR-0004、ADR-0038、ADR-0044 的无条件诊断记录要求：开启时维持原有
内容与追加格式；关闭时不产生新的诊断文件，也不删除已有日志。生成进度、事务及任务
恢复记录不是诊断日志，不受影响。显式性能测试、研究测试数据仍为测试业务工件；附件
批量测试从 `.log/attachment-preflight.jsonl` 读取的详细统计只有开启日志时才完整。

本次不引入轮转、过期删除、已有日志清理或用户界面开关；宿主自身日志与协议传输文件
由各自运行时负责，不能通过禁止协议写入来关闭它们。

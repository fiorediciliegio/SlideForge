# Visual Style Preset 使用语义配色变体

可换色的 Visual Style Preset 保持“一份预设目录、一份参考 HTML、多套命名配色”。新模板通过 `theme_mode: "semantic-v1"` opt in；每个 `color_variants[].roles` 必须完整提供 `bg`、`surface`、`ink`、`muted`、`accent_primary`、`accent_secondary`、`accent_tertiary`、`line` 八个稳定角色。参考 HTML 在根级声明对应的 `--theme-*` 变量，允许再派生模板自己的语义变量，但不把具体元素直接绑定到自动编号色槽。

前端把选择编码为“基础预设 + 配色变体”的运行时身份，列表悬停和弹窗点击通过覆盖已加载 HTML 的 CSS 变量即时预览；确认需求并加载参考 HTML 时，所选配色会写入待快照的 HTML，因此 Workspace 仍得到不可变的 Template Reference Page，而不是依赖前端运行时换色。无配色预设不显示空白颜色栏；旧预设继续兼容原有颜色迁移机制，本决策不要求一次性改造旧目录。

目录排序使用显式 `catalog_cohort: "new"` 标记新预设。预设仍先按 `score` 降序；仅在相同分数组内稳定交错 established/new，并在一侧耗尽后追加剩余项。该标记属于前端目录元数据，不能从 `ppt_number` 推断。

## 原因

- 单 HTML 避免每增加一套配色就复制整份布局、文案和预览结构。
- 八个主题角色保持跨模板一致；模板内部仍可用少量有意义的派生角色表达自身设计，而不会退化为大量无语义颜色编号。
- 选择在 Workspace 快照前物化，保留 ADR-0049 的不可变参考页契约。
- 显式 cohort 让目录混排可维护，不把偶然的编号约定变成业务规则。

## 未采用的方案

- 每套配色复制一份 HTML：维护和校验成本随配色数线性增长，容易产生布局漂移。
- 只提供任意颜色选择器：无法保证层级、对比度和模板设计质量。
- 让所有元素直接使用八个根角色：表达力不足；允许模板语义派生层，但根主题契约固定。
- 为所有历史模板立即迁移：风险和收益不匹配，保留兼容路径并让新模板逐步采用。

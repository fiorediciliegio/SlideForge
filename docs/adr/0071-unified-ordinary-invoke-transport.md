# 普通 invoke 统一传输

日期：2026-09-28。状态：已采纳。

## 背景

平台普通 invoke 的上限为 4 MiB。原有实现将约 48 KiB 的阈值、固定上传及读取引用分散在大纲、日志、研究、批量测试、HTML 预览、人工编辑与生成流程中。业务调用方必须了解传输方式，也容易遗漏完整消息、中文编码和 Base64 膨胀带来的额外字节。

本决定替代 ADR-0017、ADR-0040、ADR-0057、ADR-0064 中普通 invoke 的固定上传及 48 KiB 传输预算部分。它不改变作品权威文件、渲染校验、资源存储、截图附件或异步任务的约定。

## 决定

普通前端调用只通过 `src/runtime/invokeTransport.ts`。入口为 `app_invoke_transport`，业务工具名放在 `tool`，业务参数编码为 `payload`。引擎校验工具白名单，禁止嵌套网关或分块通道；解码后调用原业务分发，再将业务结果或错误编码返回。前端 API 和界面只看到原始业务数据。

请求和响应共用 `executas/ppt-engine/invoke-transport.js`，使用版本 1 的传输帧，带原始 JSON 字节数和编码方式。内部预算为 **3 MiB = 3,145,728 字节**，不是十进制 3 MB。

1. 将完整消息序列化为 JSON，按 UTF-8 字节计量；不超过预算时返回 `encoding: "json"`。
2. 超限时对原始 JSON 只压缩一次，gzip 后转 Base64。将编码内容、元数据与外层消息重新计量；不超过预算时返回 `encoding: "gzip-base64"`。
3. 压缩后仍超限时，把原始 JSON 作为 `application/json` 上传，返回 `encoding: "upload"` 和短期 Host Upload 引用。引用所在的完整消息仍须满足预算。

前端预算包含工具标识、网关名称、业务名称、参数和超时选项；后端预算包含真实 JSON-RPC 标识、结果包装和传输元数据。新网关及分块通道直接输出已受限的标准输出行；旧 `app_stdio.js` 只对文件指针内联实施的 1 MiB 限制仍保留。

接收方验证协议版本、编码、HTTPS 地址、MIME 类型及声明大小，解压与下载都按声明大小有界读取，并要求实际字节数一致。通用 JSON 上限为 128 MiB，既有业务内容限制继续适用，例如人工 HTML 64 MiB、候选 HTML 16 MiB、个人模板 HTML 8 MiB。这个上限约束解码资源，不等同于平台允许上传任意大小文件。

## 上传、重试与跨域

上传沿用现有 `negotiate → PUT → confirm`（协商、上传、确认）框架：暂时失败最多三次尝试，使用退避；每次重试重新协商，不复用确认失败的上传键。权限等确定错误直接返回。解码或上传失败不能触发传输层重新执行业务工具。

后端响应上传始终在原 `bindInvoke` 作用域内，反向 RPC 保留父调用的 `invoke_id`。分块完成和并发业务调用也各自保留父调用上下文；不再需要区分新旧传输的异步上下文开关。

浏览器在重试后仍发生网络类错误（包括跨域限制）时，通过 `app_invoke_transport_channel` 中转。它只处理 256 KiB 原始字节块，控制消息也经过统一发送边界的完整字节预算检查，不能再次进入上传编码器，避免递归兜底。上传依次执行开始、追加、完成、释放；下载执行准备、读取、释放。随机句柄不暴露本地路径，校验偏移、完整性和类型；临时文件在成功或失败后释放，闲置 10 分钟回收，同时最多 16 项、总容量 256 MiB。

## 业务边界与入口收敛

大纲、附件分析、研究结果、日志、批量测试等直接传原始对象；生成的艺术指导、视觉母版、页面、视觉规划、候选 HTML、个人模板 HTML 和元数据直接传文本或对象。预览、人工编辑上下文、页面源码和性能报告直接返回业务内容。原来的业务专用传输包装、引用读取接口、整文件中转接口及 HTML／Markdown 的 `_host_upload` 别名全部删除，不兼容旧版前端。缩略图直接返回 WebP data URL；压缩与上传仍由统一层选择。

`manifest.json` 只声明四个对外入口：`app_invoke_transport`、`app_invoke_transport_channel`、`app_run_pdf_export`、`app_run_export_artifact_publish`。普通业务的参数定义移入 `invoke-tools.json`，运行时分别校验两个清单与对应分发器一致。网关只能调用内部业务工具（包含任务状态机），不能嵌套网关、通道或异步白名单工具；外层分发器不能调用内部业务工具，也不接受参数自称异步来绕过限制。

Host 对普通与异步调用都使用外层 JSON-RPC `method: "invoke"`，因此这里实施的是工具名白名单，无法区分同名入口的客户端调用方式。当前前端只有 PDF 导出和导出镜像发布使用 `invokeAsyncAwait`；这两个入口的结果、错误和文件指针协议保持原样，异步恢复与结果读取也不迁移。PPTX 导出继续通过网关启动并查询状态。引擎版本和 App 最低依赖同步为 6.0.9，避免新前端静默落回缺少网关的旧引擎。

真实文件上传仍使用 Host Upload；APS 图片搜索、快照、导出镜像、预览图片和字体资源映射维持原用途。会话图片、PPTX 输入等必须拥有 HTTPS 地址的附件继续主动上传。统一层产生的 JSON 引用属于临时传输，不写入权威作品工件。

## 验证

协议测试覆盖精确预算边界、中文与 JSON 转义、压缩和不可压缩数据、声明大小错误、解压超限、上传与下载重试、跨域分块、临时文件释放和并发上下文隔离。真实 `app_stdio.js` 子进程测试验证超过 1 MiB 的直接响应、双向压缩、不可压缩响应上传、确认失败重新协商、普通直连无副作用拒绝、旧工具名及嵌套入口拒绝、任务状态机经网关调用和异步白名单的原有错误协议。前端适配测试覆盖原有业务调用和异步导出契约。

本地协议测试不替代真实 SlideForge Host、浏览器跨域策略及需要 Chrome 的渲染联调。

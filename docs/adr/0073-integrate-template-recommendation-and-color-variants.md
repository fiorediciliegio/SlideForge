# 在现有四语言与统一传输架构中接入模板推荐和配色

日期：2026-09-28。

## 决定

模板推荐改为模型从原始需求描述提取意图、本地按目录标签评分；明确排除的风格先过滤。匹配标签仅属于推荐过程，不重新引入演示需求的受众、用途等历史字段，也不提供创作事实。信号不足或模型失败时，将最多三个候选保存在需求草稿中，由用户明确选择后才能确认；手动创建及历史无模板草稿也遵守此约束。读取旧需求时缺省推荐记录为 `null`，不改写已有作品。

当前自动推荐只使用内置模板，不读取个人模板目录；个人模板入口后来由 ADR-0074 恢复，自动推荐范围不变。推荐器底层可以接受个人模板，但交互及批量入口采用相同的内置候选范围。

保留 ADR-0061（语义配色变体）的八个颜色角色、组合选择身份和确认时写入参考快照的约定。目录包含 98 套预设、861 张 WebP。首页默认使用静态图片；实时卡片在首次配色交互或选中非默认配色后才加载，弹窗按需加载，不在首页打开时批量创建实时 iframe。字体安全策略保留现有 HTTPS 支持。

新增界面文字使用现有语言包与类型定义，提供中文、英文、日文和德文。`messages.ts` 继续作为兼容导出，不恢复旧的双语大文件。

## 批量测试与传输

`template-recommendation-completed` 在推荐完成后停止，保存候选评分等诊断信息。内部批量流程直接采用首选候选，不等待人工选择。`reuse_requirements` 仅允许用于 `requirements-confirmed`：同一需求的后续重复复用首次生成的规格与研究选择，但每次重新执行模板推荐。

模板确认直接传 `template_snapshot`，由 ADR-0071 的普通调用层处理尺寸预算、压缩与上传。业务层不上传模板 JSON 或传旧的 `host_upload` 字段。推荐结果参数注册在 `invoke-tools.json`，对外 `manifest.json` 继续只公开统一网关、分块通道和两个异步入口。

批量更新继续返回完整批次对象，保留响应丢失后读取持久状态的恢复机制。暂不采用仅前端实现的精简回执；若后续优化返回结构，必须同时修改引擎、适配器及调用方并验证真实端到端契约。

## 验证重点

覆盖推荐候选与确认门槛、旧需求读取、配色快照、推荐结果持久化、重复需求的直接快照确认、正常批量更新不误入恢复、响应丢失恢复、附件 OCR 与后续流程顺序，以及四语言词条和占位符一致性。

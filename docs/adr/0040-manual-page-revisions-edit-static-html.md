# Manual Page Revisions edit static HTML directly

> HTML v1 已确认人工页面编辑与独立 HTML Page Source 契约兼容。本 ADR 描述当前用户可达的静态 HTML 人工页面修订流程。

PPT App will provide manual page editing by modifying the browser-rendered static HTML DOM directly, not by converting Deck HTML into a structured presentation model, redrawing it through React, or translating edit operations back into TSX through an AST. A saved Manual Page Revision becomes that Page Generation Unit's current content and visual version, while its existing Page Source remains the authoritative authoring source that a later Agent run can revise.

每页最多保留一份当前人工修订，位于 `manual-edits/<page_id>/`，包含 `manifest.json`、编辑起点 `base.html`、当前版本 `current.html` 和验证截图 `current.png`。工作区图片和字体使用规范绝对 `file://` 引用；源码 `slides/<page_id>.html` 保留供恢复与后续创作使用。每次成功保存递增修订号，不保存跨会话撤销记录或多版本历史。`base.html` 的起点内容保持不变，旧内嵌资源可规范化为本地资源。

Every save supplies the revision from which editing began. If it no longer matches the current persisted revision, the backend rejects the save without merging or publishing any submitted content. The editor retains its unsaved local state and offers only cancellation or reloading the latest persisted revision; the first release provides no force-overwrite path. 只有后端最新内容仍与本次编辑起点完全一致时才允许更新修订号并重试；真正的内容冲突保留原修订号，不能通过再次点击保存绕过冲突。

`current.html` 是人工修订的唯一当前 HTML，同时供页面优化、后端截图、最终演示渲染及导出读取。编辑器和结果页只在内存中派生 APS 临时地址展示版本，不再生成、上传或读取专用智能体 HTML。读取旧 manifest 时忽略 `agent_html_path`；成功保存时移除历史 `current.agent.html`。旧图片 Base64 在当前页进入新链路时按内容指纹提取为资源，保存后落盘为本地引用，不批量重写其他作品。页面优化成功采用后清除该页人工修订，保留仍被页面源码引用的资源；删除页面和全量重新生成沿用已有清理规则。

The first editor release accepts newly uploaded or replacement images only as content-verified PNG, JPEG, or WebP files, with a maximum original size of 20 MiB and maximum dimensions of 8192 by 8192 pixels. It does not accept or automatically convert GIF, SVG, or HEIC uploads. Existing page SVG and chart content is selectable as an intact object and must never be passed through the HTML absolute-promotion path, which would create invalid SVG descendants. Dedicated SVG editing may modify chart text and its position or size through SVG-native attributes and transforms; until that interaction is available, the SVG object is not resized or moved by the generic HTML controls. Remote image URLs remain URLs, but every referenced image must load successfully during backend save validation or the save is rejected without replacing the previous revision.

编辑上下文复用 ADR-0057 的传输：普通文本 → gzip + Base64（压缩文本）→ 上传引用。完整业务响应包含 HTML、资源对应关系、字体和修订元数据，按 48 KiB 预算选择分支；编辑器打开时不上传优化截图，只有 `purpose: "refinement"` 才准备截图附件。保存请求也按完整调用参数（含日志开关）的 48 KiB 预算选择这三种传输。原始内容上限 64 MiB，前后端校验字节数，解压和下载受声明大小约束。压缩文本传输不属于图片内嵌。

编辑器沿用受管字体库与工作区字体机制；字体展示使用 APS 临时地址，持久化与导出使用工作区 `fonts/` 文件。允许现有流程支持的 TTF、OTF、WOFF、WOFF2 上传。字体在后端渲染验证中不可加载时，保存失败并保留上一修订。

编辑器加载完整静态文档，但只允许修改固定 1920×1080 页面容器及其后代。保存前按会话资源对应关系将 APS 地址还原成本地引用，覆盖图片属性、候选图片集、SVG 图片、CSS 背景及字体；保留旧地址别名，因此还原无需请求过期链接，也不从签名 URL 猜测文件路径。后端按真实路径检查资源必须位于工作区的 `research/evidence/images/`、`uploaded-sources/asset/`、`page-assets/` 或 `fonts/`，拒绝符号链接越界；未还原的新远程地址会被拒绝，原文已有 HTTPS 资源仍可保留。iframe（内嵌页面）允许父页面访问 DOM，但不允许脚本、表单、弹窗、导航和下载，后端仍再次清理和验证。

插入与替换图片先独立上传，后端验证内容格式、大小和尺寸，再按 SHA-256 内容指纹存入 `page-assets/<page_id>/`，返回 APS 展示地址。HTML 不再写入图片 Base64。新建画布（含撤销、重做和切页）前检查资源有效期；刷新同时更新字体地址与到期时间。快照比较和撤销历史使用本地引用，刷新地址不计为内容修改；刷新失败保留当前画布和历史，允许重试。

Manual save does not invoke the Agent Visual Review. It performs only deterministic safety and renderability validation, including sanitization, the single fixed-size slide shell, successful resource loading, and screenshot generation. A user's visually crowded or otherwise subjective layout remains valid if those deterministic checks pass; the existing Visual Review runs only after Agent-authored TSX rendering or repair.

Manual persistence is page-scoped. The editor compares normalized content against the last successfully saved snapshot; selection, text focus, and temporary editing overlays are not content changes. 保存由用户主动触发；切页时把实际修改暂存在当前编辑会话的内存中，不弹保存确认，返回该页时恢复草稿、原始修订号和本地资源快照。草稿只在画布安装成功后转为当前页内容，连续跳页不能丢失尚未显示的草稿。点击保存、保存快捷键或退出确认中的保存时，先保存当前页，再逐页保存其他草稿；整次操作共享一个进行中的请求，切页等待保存结束，退出和恢复在保存期间不可执行。真正的修订冲突在两条保存路径中均按编辑起点校验，不能改用最新修订号强制覆盖。保存过程中新增的当前页修改继续保留；中途失败保留失败和未处理草稿，已成功保存页面不回滚。退出时对整份演示的剩余修改询问保存、放弃或取消；放弃只丢弃尚未保存的内存草稿。草稿不跨编辑会话或应用重载恢复。 A save does not wait for a whole-Deck render. After the submitted page has passed deterministic Chrome validation and its HTML and screenshot have been published, the backend atomically replaces that page's shell in the existing completed `deck.html`, preserves the completed Final Deck Render, reuses every existing page screenshot, and invalidates prior PDF/PPTX export records. Leaving the editor therefore performs no render in the normal path. If the completed Deck document is missing, structurally incompatible, or cannot be updated safely, the Manual Page Revision remains saved, Final Deck Render becomes unavailable, and leaving the editor or a later formal Review/export performs the existing full-render recovery. 恢复 Page Source 时先在隔离输出目录准备源码渲染，成功并校验并发状态后才事务移除人工修订及发布页面／整份演示，失败保留原内容。预览故障后的用户确认恢复见 ADR-0072：同页已保存静态版本会发布为普通人工修订，沿用当前页权威规则，覆盖前内容保留为随 APS 持久化的恢复材料；不新增用户可见的历史版本系统。

Full Final Deck Render continues to build the ordered Deck document in `ppt-engine`. Following ADR-0049, it combines existing static page snapshots, with a saved Manual Page Revision taking precedence over the generated snapshot for that page. Incremental manual publication uses the same shell replacement contract against the already completed Deck document and is serialized per Workspace so concurrent page saves cannot overwrite one another. Review, PDF, and PPTX therefore consume the current page version through the existing `manifest.json -> deck.html -> dom-to-pptx -> deck.pptx` chain; the frontend never assembles Deck HTML or accesses Workspace files directly.

页面列表指纹、单页预览、编辑上下文、整份演示拼装与 PDF 页面选择共用当前页面解析逻辑。有人工修订时从工作区规范位置读取 `manual-edits/<page_id>/current.html`，不依赖旧机器的绝对路径，也不因人工文件缺失而将旧源码静默视为当前版本。候选预览和创作输入保持各自语义，不套用正式页面的人工优先规则。

APS 恢复后的预览重建优先复用人工修订，发布时再次校验页面版本，不覆盖正在进行的前台渲染，不修改用户更新时间或增加创作尝试次数。打开旧作品和开始导出前，可修复完成作品中遗留的错误页面指针并重新组合静态演示；只有整份生成及恢复均已完成、页面源码仍匹配已接受基线时，才恢复被旧重建流程改坏的页面完成状态。修复使旧导出记录失效但保留文件，不重建大纲或改写人工内容；开启诊断日志时将修复事件写入 `.log/preview-recovery.jsonl`。这属于完成作品的派生产物维护，不会恢复或接受未完成创作。

When Page Refinement or Deck Refinement targets a manually revised page, every Page Authoring attempt receives context in this precedence order: the Manual Page Revision manifest, `current.html`, the current manual-page screenshot as a native Session image input, the existing TSX, Presentation Requirements, Confirmed Outline, Workspace Style Guide, and Research Evidence or other Authoring Kit inputs. `current.html` is the latest user-provided content and visual structure, the attached screenshot is visual context only, and the existing TSX is the older source or current repair candidate. The screenshot's local path is not exposed as an Agent image-analysis input. Render-fix continues to use this manual-page baseline while no new render exists; visual-review-fix instead receives the latest successfully rendered screenshot that failed review. Saved manual text and numbers are allowed user-provided content and must be preserved unless the new request explicitly changes them; neither screenshot nor the older TSX may override them as factual grounding. The existing Visual Review remains limited to visual usability checks such as overflow, overlap, cutoff, readability, contrast, missing visuals, and canvas bounds; it does not compare the manual and newly rendered versions or judge whether manual edits were preserved. The Manual Page Revision remains current through Agent, render, and visual-review failures and is deleted only when the new Page Source render reaches the existing `accepted` state.

Editor deletion is soft only in the persisted manual document: the node remains in place with `visibility: hidden` and `data-ppt-editor-deleted="true"` so surrounding layout does not reflow. The current manual HTML preserves that node and marker as an explicit user deletion instruction, and Page Authoring must omit it from the replacement TSX rather than recovering it from the older Page Source. After a successful save the first release offers no hidden-node recovery UI; only undo within the current editor page session or restoring the Page Source version can recover it.

When an edited element still participates in normal Flex, Grid, or block flow, its first move or resize promotes it to an explicitly positioned object using measured `left`, `top`, `width`, and `height` inline values. An inert, unselectable node marked `data-ppt-editor-placeholder="true"` remains in its former flow position so siblings do not reflow; elements already absolutely positioned need no placeholder. The persisted manual document retains the placeholder as layout machinery, but Page Authoring must omit it from replacement TSX because it is not user content. Unsaved-session undo may restore the original flow structure.

A full Deck Generation deletes all Manual Page Revisions when it replaces the current page identities and resets Page Sources. Deleting a page deletes its Manual Page Revision, while ordinary single-page or whole-Deck refinement removes revisions only for targeted pages that reach `accepted`. No stale-revision merge workflow, HTML automatic merge, TSX AST reconciliation, or compatibility path through the removed `PptxPresentationModel` and `ppt-gener` is introduced.

Implementation selectively ports the existing structured-editor branch's full-screen shell, filmstrip, toolbar presentation, keyboard interactions, session history, save status, exit confirmation, rich-text selection utilities, styling, icons, and localized copy into a new `manual-page-editor` feature. It does not merge or cherry-pick that branch and does not port `PresentationDocument`, its React renderer, JSON document operations, presentation-document backend, or revision store; iframe DOM selection, Moveable integration, DOM operations, and Manual Page Revision persistence are implemented against the current architecture.

This decision supersedes ADR-0021 only where it described the Page Source as the sole authority for the current visible page and every static HTML snapshot as necessarily non-authoritative. ADR-0021's browser staticization, readiness, script removal, captured CSS, and managed-Chrome requirements remain active, and ADR-0034's fixed Deck shell and direct `dom-to-pptx` export contracts remain active.

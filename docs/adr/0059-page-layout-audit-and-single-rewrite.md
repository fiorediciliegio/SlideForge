# ADR-0059：页面生成后检查布局，严重问题触发一次重写

> 2026-09-20：创作要求、文案自由度移除及修复/美化输入边界见 [ADR-0066](0066-outline-creation-requirements.md)。

> 2026-09-22：每页最多执行 3 次完整生成尝试。HTML 上传、提交或渲染失败（含布局修复后的渲染失败）时，从原始创作提示词重新开始，不将失败信息注入提示词；每次尝试最多进行一次布局修复。重新创作继续携带本页原图，布局修复仅携带整页截图及适用的创作要求、本轮修改意见。布局检查或修复上下文读取失败不触发这层自动重试；会话失败仍由会话执行器处理，取消立即终止。


状态：已采纳（2026-09-15）

## 背景

已有 `layout-audit` 能检测页面越界、容器和文字溢出、元素重叠等问题，但此前仅用于离线检查。用户要求将现有规则直接接入 HTML 生成主流程，仅处理严重问题，最多自动重写一次。

## 决策

每页首次完成 HTML 创作、持久化和浏览器渲染后，在接受前执行布局检查。App 通过 `PptBackend.auditWorkspacePageLayout` 调用引擎工具；引擎检查当前静态快照，固定使用 1920×1080，并验证源文件与渲染、截图指纹一致。完整报告写入工作区 `output/layout-audit/`，协议只返回计数及工件引用。

严重问题数为 0 时直接接受，忽略警告和可疑项。严重问题数大于 0 时，新建一次 HTML 生成会话，复用现有会话重试框架与禁用工具策略。提示词只包含用户指定的修复要求、`slides/<page_id>.html` 原文，以及当前截图附件；不使用带大量静态样式的预览 HTML，不附大纲、视觉母版、模板参考或检测报告。

重写要求保留原文字内容，修复溢出、遮挡及大量空白，并保持唯一的 1920×1080 `.slide` 根容器、正文至少 20px、次级说明至少 18px。输出仍走现有唯一完整 HTML 提取、上传、提交和渲染流程。重写成功渲染后直接接受，不再检查，也不添加第二轮布局修复。会话自身的失败重试不计作新的布局修复轮次。

新增 `layout_checking`、`layout_rewriting` 活动状态和 `layout_check_failed` 可重试失败状态。会话、上传、提交和渲染失败继续沿用原有失败分类；检测失败或缺少修复上下文不能误当作通过。取消后返回的结果不能继续提交或接受。恢复失败页仍按现有规则重新完整生成。

前端提供中英文阶段名称；布局修复保持实时 HTML 预览，修复后的静态预览和缩略图按源版本更新。初次生成、继续生成及使用同一逐页执行器的单页和整套优化沿用此规则；个人模板创建、单页候选生成和人工编辑不新增本检查步骤。

## 后果

每页增加一次浏览器检测；严重项可能增加一次完整 HTML 会话及一次渲染。沿用现有算法，包括其重叠误报与重复计数行为。本次不调整规则、不处理警告、不保证修复后的页面没有剩余问题。

# 演示需求只确认生成规格与研究选择

## 背景

需求生成原先会推断受众、用途、预期效果和视觉气质，并默认选中推荐候选。用户确认后，这些推断作为权威约束进入研究、大纲和视觉生成，可能偏离原始需求。需求确认应聚焦用户能够明确决定的生成规格和研究选择。

## 决策

- 需求页只保留生成规格（正整数页数、具体输出语言）与研究选择（网页搜索、图片搜索）。仍需要用户显式确认；保存草稿不触发后续生成。
- 从候选、选择、前后端类型和确认校验中移除 `audience`、`purpose`、`desired_outcome`、`visual_tone`。需求生成模型只返回页数候选，输出语言继续独立识别；研究推荐继续独立执行。
- 大纲生成与改写、研究推荐与执行、图片分配、模板及美学参考选择、视觉母版和整份优化提示词不再注入这四个结构化字段。原始需求中的受众、用途等明确表达继续作为用户输入生效，不再另行推断、补齐或保存内容目标。
- 保留现有模板选择流程。未选择模板时，依据原始需求与生成规格自动选择；确认时仍提交模板参考快照。模板参考与工作区视觉母版承接视觉方向，不再依赖视觉气质。
- 对当前工作区协议中的旧需求做最小读取兼容：丢弃四个已移除字段，校验并保留其他字段，后续保存仅写新结构。不迁移旧版页面协议，不自动重写已有大纲、视觉母版或页面；再次生成才使用精简需求。
- 原有页数同步、输出语言归属、研究开关和模板确认边界保持有效。未知的非历史字段仍应报错。
- 需求页面、批量测试详情和提示文案同步中英文；批量测试沿用主流程的精简契约。

## 影响

本决策替代 ADR-0022 与 ADR-0049 中要求完整内容目标及必填 Visual Tone（视觉气质）的部分，保留显式确认、模板快照、独立 HTML 页面源及视觉母版机制。新旧需求的读取、确认、研究与提示词边界需通过回归测试。

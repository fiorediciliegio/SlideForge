# PPTX 导出嵌入页面声明的字体

PPTX 导出启用 `dom-to-pptx` 的自动字体嵌入。这取代 ADR-0034 中「首次集成不启用自动字体嵌入」和「Automatic font embedding remains disabled」两处决定；ADR-0034 关于 Deck HTML 快照、固定画布、图片完整性门禁和后端导出边界的其余决定继续有效。

嵌入范围限定为 Deck HTML 自己的 `@font-face` 声明所覆盖的字体族。导出不扫描运行主机已安装的系统字体，也不为未声明来源的字体族猜测下载地址。`PingFang SC`、`Microsoft YaHei` 这类只出现在 CSS 字体栈里、没有 `@font-face` 来源的系统字体不参与嵌入，继续依赖查看器的字体可用性与回退。

字体字节由 `ppt-engine` 的 Node 进程读取，而不是在受管 Chrome 页面里 `fetch`。这是必需的：工作区托管字体（Workspace Managed Font）的 `@font-face` 使用 `file://` URL，而浏览器禁止对 `file:` 发起 `fetch`。同一条 Node 侧读取路径同时处理远程 `http(s)` 来源，使托管字体与远程字体只有一种失败模式和一处日志。`dom-to-pptx` 保留其浏览器 `fetch` 作为独立使用时的默认实现。

一个字体族在 PowerPoint 的嵌入模型里有 regular、bold、italic、boldItalic 四个槽。CSS 的 `@font-face` 声明不保证填满这四个槽，而浏览器会在族内跨样式回退、PowerPoint 不会。因此嵌入前回填空的 regular 槽：族内已有任一字形面时复用它，使该族在查看器中始终可解析，而不是整族回退到替换字体。已显式声明的 bold、italic、boldItalic 槽不被覆盖。

同一个字体文件 URL 可能被同族的多个字重共用（Google Fonts 对可变字体即如此），因此字体发现按「族 + 槽」去重，而不是按 URL 全局去重。按 URL 全局去重会让先命中的字重独占该文件，同族其他槽变空。

字体族发现遍历元素计算出的完整 CSS 字体栈，而不只取栈首。只取栈首会漏掉那些把系统中文字体放在前面、把网络字体放在后面的字体栈。

中英混排的文本 run 单独解析东亚字体槽：从该 run 的 CSS 字体栈里取第一个实际覆盖 CJK 字形的字体族写入 `<a:ea>`，而不是把拉丁字体名同时写进 `<a:latin>`、`<a:ea>` 和 `<a:cs>`。嵌入一个真实存在但没有中文字形的拉丁字体后，`<a:ea>` 指向它会让中文按查看器自身的东亚替换表回退，落到与浏览器不同的字体上。

字体嵌入失败不使 PPTX 导出作业失败。失败的字体族记入导出作业警告，与既有的托管字体变体警告并列但字段独立，因为两者的用户含义不同：一个是字形被替换，一个是粗体或斜体被模拟。ADR-0034 的「字体就绪是尽力而为」保持不变。

本决定不承担字体授权判定。当前阶段的字体来源是本地开发用的演示素材，导出不检查字体的嵌入许可位，也不维护许可白名单。

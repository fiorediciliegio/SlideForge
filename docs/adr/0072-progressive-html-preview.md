# ADR-0072：HTML 预览渐进展示与当前页准备名额

- 状态：已采纳
- 日期：2026-09-28
- 调整：ADR-0057 中等待 iframe 加载完成才展示页面的规则；ADR-0064 的已加载页面保留规则继续有效。

## 背景

结果页在 iframe 的 `load`（加载完成）事件之前一直遮挡页面。图片较慢时，即使 HTML 已经到达、文字可以绘制，用户仍只能等待。四个后台页面同时准备时，刚选中的页面也可能无法挂载。

## 决策

1. 共用 HTML 预览区分“可以展示”和“资源加载完成”。当前页 HTML 到达并挂载 iframe 后立即可见，移除遮挡内容的加载提示，允许浏览器渐进绘制文字、背景和图片。HTML 获取期间保留旧画面及加载提示；不读取沙箱内部 DOM，不增加脚本权限。
2. `prepared` 表示 iframe 已挂载、资源可能仍在加载，选中时可以展示；`ready` 仍由 `load` 确认。提前展示不调用完成回调、不释放准备名额。现有错误、30 秒准备超时和重试处理继续有效；可见页面失败时进入下面的确认恢复流程，不显示其他页面冒充当前页。
3. 每个预览会话最多同时准备四个 iframe，其中后台最多三个，为当前页保留一个名额。快速跳页时，若四个名额已占满且新选中页 HTML 可用，暂停一个优先级最低、尚未完成且不可见的后台 iframe，将 HTML 放回待准备状态，再挂载当前页。重新准备前仍校验资源地址有效期。
4. 已加载完成的 iframe 不被上述调度淘汰。旧画面等待新 HTML 时继续保留；晚到的后台加载不能改变当前选择，旧版本晚到不能恢复已移除页面。HTML 获取并发上限仍为十。
5. 缩略图、权威 HTML、原始图片和导出输入保持现有契约。共用候选预览也提前显示，但其外层准备队列仍等待加载完成或失败后释放名额。

## 验证与限制

状态与调度测试覆盖提前可见、前台预留名额、连续跳页的四路上限、旧版本替换、过期 HTML、晚到事件和失败重试。DOM 挂载测试在不触发 iframe 加载完成事件的情况下，确认当前页可见且无遮挡层、完成回调未触发、已加载 iframe 可复用。

DOM 测试不模拟真实图片下载和浏览器绘制。实际文字首次出现时间、图片补齐时的布局变化仍需在运行中的 App 验证。后端资源地址准备及 HTML 获取耗时不属于本次优化；未预留图片尺寸的页面仍可能发生布局移动。

## 2026-09-29：单页故障隔离与确认恢复

- 正式页面加载允许一次自动重试：版本变化重新读取当前版本，资源准备失败或临时传输错误也只重试一次；单次等待有上限。iframe 自身准备失败也有一次有界重试。候选始终校验原候选身份与版本，不借用正式页或其他候选。
- 仍不能加载最新版时，不自动展示历史 HTML 或缩略图冒充当前页。当前可见页面读取可恢复选项，有可编辑版本才弹窗，明确说明来源与替换效果。支持原始生成版、人工编辑前版本或同页已保存静态版本；图片不构成可编辑恢复选项。后台预加载、缩略图、生成中的页面及隐藏保留的结果页不弹窗。
- 用户取消后保留页位、标题、页码和“重试／使用已有版本”入口，该页不渲染，也不影响其他页。同页同版本不会因重挂载自动重复弹窗。候选过期、失败及取消均不修改正式内容；提交失败不会自动重放写请求。
- 确认调用携带准备阶段返回的版本令牌。后端先在独立输出目录准备内容，完成页面壳及本地资源校验，再检查原文件和当前操作状态，使用现有多文件发布事务提交。等待期间出现人工保存、源码变更、页面变化或活跃生成／渲染／导出时拒绝覆盖。人工保存与恢复串行，提交失败回滚，重开时复用现有事务日志恢复。
- 原始源码恢复成功后移除当前人工修订；已有静态版本恢复则发布为普通人工修订，继续使用统一的当前页解析规则，避免 APS 丢弃派生输出后再次回到旧源码。覆盖前的源码与人工文件保留在 `manual-edits/.recovery-backups/<page_id>/<operation_id>/`，随现有 APS 白名单持久化，不新增用户可见的历史版本管理功能。
- 正式发布同步页面指针、修订状态、整份静态演示和导出失效状态，通过正常修改回调刷新前端元数据、预览及缩略图版本，恢复正常编辑、优化与导出路径。后端触发快照，前端同时沿用专用 Host invoke 的 APS 发布授权路径。其他页面仍损坏时，本页可先恢复，整份演示标记待重建，不能导出残缺结果。
- UI 元数据读取显式使用 `allow_partial`，为缺失产物的页面保留身份、页序与不可用标记，单页失败不使整份列表失败。生成验收继续严格读取；编辑、生成和导出不接受未经确认的备用 HTML。
- `preview-recovery` 是独立于详细诊断开关的轻量告警，记录预览失败、自动恢复、取消、确认恢复成功与失败。只接受页面 ID、错误类别、请求／实际指纹、恢复来源及结果；一分钟内去重，超过 2 MiB 后轮换且只保留一份上一文件。不记录 HTML、资源 URL 或原始错误，告警失败不阻断业务。

验证覆盖：取消与再次打开、隐藏页不弹窗、确认后可编辑及优化、重复点击、传输失败、令牌冲突、切页后晚到结果、发布失败保护、丢弃派生输出后人工内容保留，以及多页损坏时逐页恢复。DOM 测试用 linkedom 模拟原生 dialog 的打开／关闭，不替代实际浏览器、云端 APS 或真实导出验收。

## 2026-09-30：生成页保持同页预览连续

- 并发生成任务只把自己负责页面的进度合入共享状态。流式事件读取共享最新状态，写入及轮询返回的整份旧快照不能覆盖其他页面；同页合法重试继续按实际执行顺序展示。
- 生成阶段记录使用本页阶段和尝试标识，不再依赖其他页面最后发送的全局阶段。每页详细过程默认折叠，展开状态由用户控制，不按完成事件自动开合。（逐页详情展示现由 [ADR-0076](0076-compact-page-generation-status.md) 的紧凑状态卡片替代，内部阶段标识规则继续有效。）
- 实时 HTML 使用固定 250 毫秒更新间隔，保留两个 iframe 交替展示。更新期间保留当前帧，新文档在浏览器绘制调度后渐进显示，不等待图片、字体全部触发 `load`。不读取沙箱内部 DOM，也不增加脚本权限。
- 当前页有有效快照时即可在实时画面背后准备正式 HTML。验收后，正式 HTML 可见才撤下实时画面；同页新版本准备期间保留已展示内容并标注更新中，切到其他页面时不借用上一页画面。可见的旧 iframe 即使图片尚未加载完成，也可在同页替换期间保留。
- 生成页缩略图按页面身份保留组件；修复期间不清空已显示小图，新版本图片加载后再替换。尚未产生当前快照时不请求旧版本内容，过时响应不能覆盖新版。其他缩略图入口沿用按版本重建组件的边界。

验证使用受控并发任务及 DOM 模拟，覆盖旧流事件、写入响应和轮询响应交错、持续输出、慢资源、同页版本替换和切页隔离。模拟测试不替代真实浏览器绘制及 APS 网络耗时测量。

## 2026-09-30：正式结果页更新时隐藏旧版本

- 正式结果页收到新页面版本后，变化页不再借用同页旧 iframe。新 HTML 获取及准备期间显示现有加载状态，避免候选采用或优化返回后短暂呈现旧结果；未变化页继续复用原 iframe。
- 新 HTML 挂载后仍立即渐进展示，不等待图片、字体全部加载完成。旧版的迟到响应及加载事件不能恢复旧画面。
- 共用预览默认继续保留同页旧画面，仅正式结果页关闭这项显示策略。生成页、普通预览、候选预览、缩略图及准备队列沿用原有规则。

DOM 回归覆盖候选采用、优化及人工编辑返回后的等待状态、新版提前可见、未变化页面复用和旧版迟到响应；生成页的同页预览连续测试继续有效。

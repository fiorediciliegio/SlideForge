# ADR-0060：单页美化复用并发候选流程

> 2026-10-09：用户入口及配置、生成、选择文案统一使用“布局修复”，默认方案数改为 2；“批量重新生成”仍默认 4。两种配置页均说明 AI 输出可能不同，可同时生成多个方案供对比选择。布局修复页以只读形式完整展示标题、大纲及已有的全局/本页创作要求，大纲不加入修复提示词。界面覆盖中文、英文、日文、德文；内部 `beautify` 模式及候选协议不变。按照 [ADR-0075](0075-single-authoritative-page-source.md)，修复输入使用当前已保存的页面，包含人工修改，确认采用后才替换当前页；下文关于人工编辑前源码的早期约定已被替代。

> 2026-09-20：创作要求、文案自由度移除及修复/美化输入边界见 [ADR-0066](0066-outline-creation-requirements.md)。


状态：已采纳（2026-09-15）

## 决策

在“批量重新生成”旁提供“布局修复”，进入独立配置页选择 1～10 个方案，默认 2 个。配置页仅设置方案数量，并完整展示只读的标题、大纲及已有创作要求，不编辑大纲或配图。生成状态、候选预览、放大预览、全部尝试结束后选择及确认替换，复用 ADR-0053 的交互和样式，并提供中、英、日、德四语文案。

批次增加 `regenerate` / `beautify` 模式；旧批次按 `regenerate` 读取。美化创建时从引擎的正式大纲获取页面标识和页序，不采纳调用方传入的大纲修改或模板参考。最新批次查询可按模式筛选。

## 输入与会话

美化只读取 `slides/<page_id>.html`，不读取 `output/page-preview-html/` 作为提示词。源码复制到批次 `input/slides/`；当已有截图的源指纹匹配且不存在人工修订时复制该截图，否则在批次输入目录单独渲染原始源码，保持原页序和总页数。输入准备前后检查正式内容指纹，拒绝版本变化造成的混用。输入准备不发布正式页面或改变人工修订。

人工修订保存在 `manual-edits/`，与 `slides/` 分离。本功能始终基于人工编辑前的源码；配置页说明这一点，采用确认再次说明覆盖人工编辑。

源码和截图通过上传引用返回，前端读取一次源码并供所有候选共享。每个候选开启独立会话，复用 ADR-0059 的布局修复提示词及截图附件机制；不附加大纲、视觉母版、模板参考或检测报告，也不附加常规创作系统提示词。会话关闭工具访问，只返回唯一完整 HTML，由应用上传并交由引擎渲染。输入附件失败不能退化成无图生成；单个会话失败只影响该候选。

## 采用与清理

沿用现有候选隔离、执行租期、版本冲突检查和短期发布日志。采用美化候选只替换当前页源码、静态 HTML 和截图，组合更新整份演示，并使旧导出失效；大纲文件和模板参考选择文件保持不变。正式内容在用户确认采用前仍然有效。

采用成功后清理候选及批次输入文件，保留最小采用记录。无需先运行布局检测，不增加自动视觉评审或循环修复；提示词约束不等于对模型输出的视觉质量保证。

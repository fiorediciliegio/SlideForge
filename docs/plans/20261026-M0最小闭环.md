# M0 最小闭环开发计划：brief → pptx

- 状态: active · 2026-10-26
- 依据: [product-tech-charter.md](../product-tech-charter.md) §七 路线
- 目标: **一条命令，从一段文字需求到一个能在 WPS 里正常打开的 PPTX**
- 时间盒: 约 4 个工作日；第 0 步为决策门，只给半天

```bash
slideforge generate --brief "Q3 销售复盘，20 页" --out q3.pptx
```

## 明确排除（防 scope 蔓延）

Web 界面、账户/计费、MCP、多模板选择、母版优化、WPS 插件、Web 研究、附件解析、图片检索、手工编辑——M0 一概不碰。

## 步骤

### 第 0 步 · 引擎独立启动 spike（半天，决策门）

- `executas/ppt-engine` 内安装依赖、构建，直接起 HTTP 服务（`src/cli.ts` / `src/http/server.ts`）
- 不起宿主、不起前端，纯命令行让引擎把一页 HTML 渲染并导出成 pptx
- **验收门**：通过 → 继续；不通过 → 回到计划，引擎服务化升为 M0 最大工作项

### 第 1 步 · LLM 直连适配层（1 天）

- 最小 `LlmClient`：OpenAI 兼容端点直连（`OPENAI_BASE_URL` / `OPENAI_API_KEY` / `OPENAI_MODEL` 环境变量），实现 `complete()`，流式可选
- 替换 `src/ai/aiClient.ts` 工厂的宿主分支
- **不做**：agent 会话、工具调用、fresh_session 重试
- 复用：`src/ai/` 全部提示词与 `structuredJson` 容错链
- **验收门**：大纲 prompt 直连模型 + 结构化解析跑通一次

### 第 2 步 · 极简编排器（1~1.5 天）

Node 入口 `scripts/m0-generate.ts`：

```
brief → 大纲生成（复用 outlinePrompt）
      → 固定一套默认模板（M0 不做选择器）
      → 逐页生成 HTML（复用页面生成 prompt，写入引擎工作区）
      → 调引擎导出 pptx
```

- **验收门**：单页失败重试一次可用；20 页跑完不中断

### 第 3 步 · 端到端联调（0.5~1 天）

工作区落盘、引擎调用、导出管线全链路串接；处理接线问题。

### 第 4 步 · 验收（0.5 天）

- 3 个真实 brief：销售复盘 / 产品介绍 / 培训课件，各产出一份
- 每份在 **WPS 和 MS Office 各打开一次目检**，记录走样类型
  → 记录即总纲 D6"保真基线"第一版数据；顺带验证已知 WebP 导出丢图 bug
- **验收标准**：排版可读、无丢图、文字可编辑

## 风险

| 风险 | 应对 |
|---|---|
| 引擎 server 模式不完备 | 第 0 步决策门拦截，半天出结论 |
| 编排逻辑与 React 状态纠缠 | 只复用纯逻辑（prompt/workflow），状态在编排器里重建 |
| WPS 导出实际走样 | 第 4 步记录清单，转入 D2 方言契约处理 |

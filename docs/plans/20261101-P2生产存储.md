# P2 生产存储实施计划

- 状态: done
- 日期: 2026-11-01
- 最后验证: 2026-11-01
- 依据: 总纲的数据单一事实源与跨域 API 纪律

## 目标

按服务边界把单实例 JSON 元数据迁移到生产存储。每个域独立选择实现，不允许 Node、Python 或其他服务直接连接 Go 的认证计费数据库。

## P2-A 认证计费 PostgreSQL（done）

- `DATABASE_URL` 启用 Go `PostgresStore`，缺省继续使用本地 JSON。
- API key、余额、幂等回执与台账使用 PostgreSQL；扣费行锁与事务保证并发一致性。
- `SLIDEFORGE_MIGRATE_JSON=true` 执行一次 JSON 导入，迁移标记与数据同事务提交。
- 迁移完成后禁止 JSON 与 PostgreSQL 双写。

## P2-B 任务存储与分布式通知（done）

- 任务快照迁移到 `deck_jobs`，更新与 `pg_notify` 同事务提交，其他实例通过 `LISTEN` 获取变化。
- 任务更新同时写入 `job_outbox`，worker 使用 `FOR UPDATE SKIP LOCKED` 竞争领取并标记投递结果。
- `SLIDEFORGE_MIGRATE_JSON` 同时执行认证计费和任务的单次迁移，禁止双写。
- `JOBS_DATABASE_URL` 支持独立任务库，缺省复用 `DATABASE_URL`；认领时间与实例 ID 分别避免重复投递和本实例重复 SSE。

## P2-C 文件元数据与对象存储（done）

- `deck_files` 保存归属与对象键，S3 SigV4 负责二进制 Put/Get，本地路径不再作为跨服务契约。
- `FILES_DATABASE_URL` 支持独立文件库，缺省复用 `DATABASE_URL`；历史对象逐个上传后记录迁移标记，缺失 `createdAt` 自动补齐。
- 公共下载继续按 API key 鉴权，再由 Go 从 S3 读取，不共享本地目录；元数据写入失败会调用 `DeleteObject` 清理孤儿对象。

## P2-D 多实例门禁（done）

- `GATEWAY_REPLICAS>1` 强制要求认证计费、任务、文件 PostgreSQL 与 S3 全部配置，并禁止多副本同时迁移。
- 提供 `slideforge-gateway@.service` 与 Nginx `least_conn` 示例；默认仍单实例。
- Node 生成队列、导出幂等、内存限流和 Chrome 工作区继续单实例，不引入分布式重复执行。
- `tests/server/multiReplicaSmoke.test.ts` 已通过真实 Docker PostgreSQL 加两个独立 Go 网关进程的联合验收：副本 A 签发的 key 可在副本 B 查询余额；跨副本 SSE 收到 `ready`；两个 dispatcher 只发送一次 webhook；文件可跨副本列出并下载；取消状态可跨副本读取。
- 三个存储的并发 schema 初始化使用同一个 PostgreSQL advisory lock。测试在宿主机 TCP 就绪后启动网关，避免把容器内 Unix Socket 的就绪误判为外部连接就绪。
- 本验收的 S3 是测试内共享对象存储模拟服务，不冒充 MinIO／云 S3 验收；Nginx 故障切换、真实对象存储、断连重试和负载测试仍需在部署环境验证。

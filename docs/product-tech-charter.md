# SlideForge 产品与技术总纲

> 版本：v1 · 2026-10-14 · 状态：**已定稿，开发基准**

## 一、产品定位

**SlideForge 是 AI 生态的 PPT 交付层。**

不做平台，不做对话框。用户在 Claude / Kimi / Cursor 等 AI 客户端里表达意图，SlideForge 负责给出"敢拿去汇报"的 PPT 文件。

> 对话归生态，保证归我们。AI 越强，我们越强——我们是它能力的落点，不是对手。

核心卖点（对通用 AI 的差异化）：

1. **保真**：确定性引擎兜底排版与品牌资产（logo 零失真），不赌模型发挥；
2. **可审计**：AI 每次改动输出机器 diff 的偏离度报告，"没动别处"是可验证的事实；
3. **可交付**：导出的 PPTX 在 WPS / Office 里打开零走样、可继续编辑。

## 二、垂直方向

| 方向 | 角色 | 依据 |
|---|---|---|
| **企业市场/品牌部** | 主钱袋（席位年费） | 品牌合规 = logo 保真 + 偏离度审计，正中壁垒 |
| **金融/咨询** | 灯塔客户（高价标杆） | 事实边界 prompt 体系（来源归属 + 时效标注）现成 |
| **政企/事业单位** | 自托管版自然延伸 | 中文一等 + WPS 兼容 + 私有化，独家组合 |
| C 端个人/教育 | 免费流量池 | 不指望收钱，攒口碑与模板生态 |

**纪律**：不确定垂直方向就开发 = 性价比无根。所有功能优先级以"是否服务主垂直"裁决。

## 三、商业模型

- **点数制计费**：对内按 token 计量（Go 网关自动折算），对外按点数收费（生成一页 ≈ X 点、高清导出 ≈ Y 点）。token 是成本单位，点数是计价单位，中间隔换算层；
- **付费墙设在导出**：生成、预览、修改全免费；高保真 PPTX 导出扣点。用户见到成品再付钱；
- **BYOK**：自带模型 key 的用户只收引擎/存储点数——开源口碑来源 + 企业版钩子；
- **企业版**：自托管授权 + 控制台（权限/审计/成员管理），按年收费。

## 四、产品形态：能力层唯一，双客户端平等

```
        ┌── Web 薄壳（客户端 A：预览/指改/资产管理）
用户 ──►│
        └── AI 生态（客户端 B：MCP / API）
                  │
                  ▼
          能力层（Capability API）   ← 系统功能唯一入口
                  │
                  ▼
            引擎 + 存储
```

**铁律**：Web 能做的每件事经由能力层完成；能力层每个功能 AI 都能调用。禁止 UI 专用后门接口。

- Web 壳刻意做薄：画布预览、鼠标指改、品牌资产管理、企业控制台。编辑器持续瘦身，不对标 PowerPoint；
- AI 客户端承载：零门槛入口、对话驱动、批量自动化；
- 像素级精修**主动让给 WPS**——"终稿在你最熟悉的工具里完成"是卖点不是缺陷。

## 五、架构决策（D1–D6，已决策）

| # | 决策 | 结论 |
|---|---|---|
| D1 | 交付定位 | 生成器 + 交接，不做编辑器替代 |
| D2 | **HTML 方言契约** | HTML 从自由格式降级为受限方言：白名单元素均有 OOXML 1:1 映射；生成后静态校验，越界拒收。导出保真从"尽力而为"变"数学必然" |
| D3 | 回传语义 | WPS 改过的 pptx 回传 = 开新分支 + AI 语义吸收 + 人工确认清单。**禁止双向同步**（必丢信息） |
| D4 | WPS 插件 | 第二阶段做。先做半天 spike：确认 WPS 开放平台 JS 加载项能写回当前文档 |
| D5 | 编辑器瘦身 | 随重构顺手执行，不单独立项 |
| D6 | 保真硬指标 | "WPS 打开零走样"模板集回归进 CI（依赖 D2 落地） |

## 六、技术架构

**三语言分工**（按负载性质切分）：

- **Node/TS（保留）**：ppt-engine 引擎——渲染栈是 JS 生态（react-dom SSR、puppeteer、vendored dom-to-pptx），不迁移；
- **Go（骨架层）**：网关（鉴权/限流/计费点数折算）、LLM 网关（SSE 流）、任务队列、文件服务、WebSocket 进度；
- **Python（大脑层）**：prompt 编排管道、文档理解（python-pptx/PyMuPDF）、偏离度图像分析、evals 评测。

**三条纪律**：契约先行（`contracts/` 目录 OpenAPI/Proto，三端各自生成客户端）；数据单一事实源各有归属，跨域走 API 不直连库；服务从 3 个起步不拆碎。

**两件新建关键资产**：

1. **元素寻址协议**：每页生成时输出元素清单（id/类型/语义/位置），AI 客户端经清单把"左上角那张图"翻译成确定性 `el:` 地址——现有骨架锚点约定（`data-*`/占位符）升级为正式规范；
2. **异步 job 协议**：调用即返 `job_id`，进度走 SSE/webhook，可取消。原平台的 job 模型机制继承。

## 八、风险登记

| 风险 | 等级 | 对冲 |
|---|---|---|
| 入口依赖 AI 生态（平台风险） | 高 | 品牌资产托管粘性 + Web 壳兜底 + WPS 插件独立入口 |
| WPS/Office 导出走样 | 高 | D2 方言契约 + D6 CI 回归 |
| 通用 AI 原生做好 PPT | 中 | 不做对手做落点；保真与审计是模型短期给不了的 |
| 双客户端维护成本 | 中 | Web 壳做薄的纪律 |

# D4 spike：WPS 插件可行性验证（2026-10-30）

- 状态：本机实机验证通过，跨机器文件交付待实机验收
- 结论：**WPS 插件可行，且存在"内容级写回"的意外收获（PasteHtml）**

## 已验证（官方文档）

1. **WPS 客户端 JSAPI 加载项**支持演示文档：加载项是运行在 WPS 内部的 Web 工程，可直接操作当前文档。官方演示 API 示例：`Application.ActivePresentation.Slides.Add(1, 1)`、`SaveAs`——**写回当前文档成立**。[WPS 开放平台 · 演示 API](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/wpp/Presentations/member/Application "citation")
2. **WPS WebOffice** 演示接口提供 `ActivePresentation.PasteHtml(HTML, Options)`——**可直接把 HTML 内容粘贴为幻灯片元素**，与我们的 HTML 原生生成链路天然契合；另有 `ReplaceActiveSlide({UploadId, FileKey})`（服务端文件替换当前页）。[WPS WebOffice · ActivePresentation](https://solution.wps.cn/docs/client/api/PPT/Presentation.html "citation")

## 集成架构（M3 插件形态）

```
WPS 加载项（任务窗格侧边栏）
  · 输入 brief / 指改指令
  · 经 SlideForge Go 网关（本机端口 8080）调用生成、导出和下载接口
  · 结果写回当前演示：
    A. 文件级：生成 pptx → 打开或插入当前文档（首选，保真路径已验证）
    B. 内容级：PasteHtml（WebOffice 场景，备选）
```

## 三条写回路径对比

| 路径 | 保真度 | 依赖 | 建议 |
|---|---|---|---|
| A. 生成 pptx → 打开/插入 | 高（走既有导出管线） | 本地 HTTP 服务 | **M3 首选** |
| B. PasteHtml | 待实测（HTML→形状的映射规则） | WebOffice | 后续探索 |
| C. ReplaceActiveSlide | 高 | 云端部署 + 上传 | 云版再做 |

## 实机验收

2026-11-06，用户在 Windows WPS 演示 12.1.0.29161 验收通过。SlideForge 侧栏可以生成并导出两页 PPTX，将它们插入当前演示后，原有第一页保留，文稿从一页变为三页。

跨机器文件交付的验收点是加载项通过网关鉴权下载 PPTX，写入 WPS 客户端临时文件并插入当前文稿。插入后修改一页，保存并重新打开，确认页数和修改保留。
